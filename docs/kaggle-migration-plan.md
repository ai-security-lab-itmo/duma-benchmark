# DUMA-Bench: минимальный runtime для Kaggle

## Цель и границы

Вместо установки всего исследовательского DUMA подготовить отдельную минимальную
Kaggle-сборку из общих исходников доменов и проверок. Все изменения выполняются
в `codex/kaggle-benchmarks`. Основной CLI сохраняет работоспособность. Публикация
и слияние в `main` не входят в рефакторинг.

Приватные ресурсы:
- [Dataset](https://www.kaggle.com/datasets/ivanblch/duma-bench-private-pilot-runtime)
- [Pilot](https://www.kaggle.com/benchmarks/tasks/ivanblch/duma-pilot)

Установка старой полной сборки проверена. Валидного модельного прогона пока нет:
последний запуск остановился на `User location "RU" is not supported for this
model/API`. Новая упаковка этого ограничения не устраняет. Такой отказ не является
нулевым benchmark score или результатом ASR.

## Целевая архитектура

- Общее ядро: модели задач и сообщений, восемь доменов, инструменты, состояния,
  политики, материалы атак, логика solo/dual и проверки.
- Нейтральный generation dispatcher; target, user и judge используют Kaggle SDK.
  Legacy LiteLLM загружается только при выборе старого транспорта.
- Минимальная точка исполнения возвращает существующий `SimulationRun`, не
  импортируя экспериментальный runner, отчётность или серверы.
- Kaggle-обвязка задаёт строки оценки, повторы, сохранение, resume и агрегацию.
- Дистрибутив `duma-kaggle-runtime` собирается из подмножества общих исходников.
  Полный DUMA и минимальный wheel не устанавливаются вместе.
- Прямые зависимости: Pydantic, docstring-parser, typing-extensions, Loguru.
  Kaggle SDK предоставляет хост; его провайдерские зависимости не обновляются.

## Этапы и критерии приёмки

### 1. Зафиксировать эталон поведения

Сохранить контракты 35 задач: материалы, состояния, промпты, схемы инструментов
и scoring basis. Записать сценарии обоих режимов, нарушения, начальную историю,
judge, ошибки и завершение. Игнорировать при сравнении только время и случайные UUID.
Приёмка: эквивалентность проверяется офлайн, без платных API.

### 2. Отделить ядро от инфраструктуры

Перевести агент, симулятор и judge на нейтральный dispatcher. Отделить JSON I/O,
пути, время, хеширование и cost от старого транспорта. Сделать pandas, YAML/TOML
и diagnostic diff ленивыми импортами. Сохранить рекурсивную семантику обновления
DB без Addict. Старый runner делегирует общему исполнителю, CLI загружает `.env`.
Приёмка: минимальный путь не импортирует LiteLLM, Langfuse, Redis, FastAPI,
визуализацию, pandas или старый runner; регрессия основной версии проходит.

### 3. Собрать переносимый runtime

Собирать отдельный wheel, исходные JSON/Markdown и протокол. Не включать CLI,
серверы, обучение, визуализацию, инструменты разработки и legacy-провайдеры.
Исходный pyproject и lock-файл не используются для установки в Kaggle. Удалить
обходы конфликтов LiteLLM/Langfuse и pins провайдерских пакетов хоста.
Проверять SDK до инференса, манифест и каждый файл до установки; поддерживать
архивированный и распакованный Dataset. Приёмка: чистая установка с четырьмя
прямыми зависимостями, без автоматического обновления хоста.

### 4. Адаптировать запуск и метрики

Строка оценки: домен, task ID, режим, номер повтора и seed; target задаёт Kaggle.
User/judge закреплены в протоколе, без автоматической замены. Environment scoring
сохраняется для 35 задач; NL scoring только для 9 задач с NL в reward basis,
а не для всех 22 задач, содержащих текст NL assertions.

Основной score: средняя доля успешных повторов по задачам с равным весом задач.
Доменные результаты отдельные. Failure rate и pass^k названы явно; обычный pass@k
не добавляется под названием pass^k. Смешанные протоколы, код, данные, SDK,
targets и режимы не агрегируются вместе. Неполная матрица не имеет итогового score.

Различать success/policy failure, technical error и incomplete; сохранять
траектории, assertions, покрытие и usage/cost. Неизвестная стоимость остаётся null.
Атомарные checksummed checkpoints и эксклюзивный lock; resume только завершённых
результатов с совпадающей идентичностью. Технические попытки сохраняются отдельно.
По умолчанию выполнение последовательное. Приёмка: готовые эпизоды не вызывают
модели повторно; повреждения и пропуски не скрываются итоговой метрикой.

### 5. Проверить и развернуть приватно

Порядок: офлайн-эквивалентность; hosted readiness без инференса; один hosted-эпизод;
solo и communication judge; пилот 3 задачи x 2 режима x 3 повтора x 2 target-модели
(36 эпизодов). Затем оценка всех 35 задач. Модельные этапы выполняются только после
подтверждения доступности закреплённых моделей для аккаунта.

Solo и dual имеют раздельные задачи оценки. Публичные коллекции требуют отдельного
решения. До релиза проверить видимость всех ресурсов и лицензии: старый Dataset
показывал `unknown` в метаданных, хотя исходный LICENSE -- MIT.

## Тесты и допущения

- Содержание задач, политики, промпты, схемы и assertions не меняются ради переноса.
- Полный протокол: seeds 300--302, максимум 100 шагов и 10 ошибок. Диагностические
  ограничения имеют другую версию и не смешиваются с итоговыми результатами.
- Сравнить действия, состояния, истории, завершение и scoring старого и нового
  движков на записанных ответах. Проверить пользовательские инструменты и solo done.
- Проверить judge JSON, API errors, лимиты, повреждения, эксклюзивный lock,
  resume, неполные повторы, веса задач и pass^k.
- Отдельно проверить чистый wheel и регрессию полного DUMA.
- Сохранить SDK-адаптер и строгую проверку judge. Прекратить установку полного
  DUMA в Kaggle и исправление конфликтов его ненужных зависимостей.
- Полностью завершить рефакторинг после валидного приватного пилота. GPU-модели,
  воспроизведение чисел статьи и публичный релиз -- отдельные этапы.
